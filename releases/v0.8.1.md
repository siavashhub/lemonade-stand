# v0.8.1

_Release date: 2026-07-26_

Hotfix for connecting to a Lemonade server that enforces an API key, plus fixes
for a batch of early feedback ([#28](https://github.com/siavashhub/lemonade-stand/issues/28), thank you @PCAssistSoftware).

## Fixed
- **API key auth** ([#29](https://github.com/siavashhub/lemonade-stand/issues/29)):
  the server-status probe and other direct server calls now send the
  `Authorization: Bearer <key>` header. Previously these hand-rolled requests
  bypassed the OpenAI SDK, so a server launched with `LEMONADE_API_KEY` answered
  `/api/v1/health` with `401` and the app showed as offline. Unauthenticated
  local servers are unaffected. (thank you @Neokeek)
- **Memory server couldn't save** ([#28](https://github.com/siavashhub/lemonade-stand/issues/28)):
  the Memory tool read fine but failed to create entities with
  `ENOENT: no such file or directory` in packaged builds. Its knowledge-graph
  file (`memory.jsonl`) defaulted to a path *inside the read-only app bundle*, so
  every write failed (and a restart couldn't fix it). It's now pointed at the
  app's writable per-user data directory via `MEMORY_FILE_PATH`, which an
  explicit env/`.env` override still supersedes.
- **Broken "Learn more" link** ([#28](https://github.com/siavashhub/lemonade-stand/issues/28)):
  the Pantry's SQLite entry linked to a page that now 404s (the reference server
  was moved to the `servers-archived` repo). Updated to the archived location.
- **Clearer "can't reach server" hint** ([#28](https://github.com/siavashhub/lemonade-stand/issues/28)):
  when an HTTP server (e.g. the Lemonade Gateway) is unreachable, the Pantry now
  shows a plain-language hint instead of a bare `TypeError: fetch failed`. For the
  Lemonade Gateway it points out that the `/mcp` gateway may not be running even
  when chat on `/api/v1` works; the raw error is still available on hover.

## Security
- **brace-expansion** ([GHSA-mh99-v99m-4gvg](https://github.com/advisories/GHSA-mh99-v99m-4gvg)):
  pinned the transitive `brace-expansion` dependency to `5.0.8` via an npm
  `overrides` entry, clearing a high-severity denial-of-service advisory
  (unbounded expansion causing an out-of-memory crash).
